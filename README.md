# Budapest Explorer

Статический сайт для GitHub Pages с Supabase Auth и PostgreSQL. Не требует собственного сервера: секреты и `service_role` не попадают в браузер.

## Запуск

1. Создайте проект Supabase. В **SQL Editor** выполните [`supabase/schema.sql`](./supabase/schema.sql).
2. В **Authentication → URL Configuration** укажите URL GitHub Pages как `Site URL` и добавьте его в `Redirect URLs`. Для локальной проверки также добавьте `http://localhost:8000`.
3. В [`config.js`](./config.js) вставьте Project URL и publishable/anon key из **Connect**. Это публичный ключ; `service_role` сюда никогда не добавляйте.
4. Зарегистрируйте владельца, затем выполните последнюю закомментированную команду из SQL-файла, подставив его email. Она назначит роль администратора.
5. Отправьте репозиторий на GitHub в ветку `main`. В **Settings → Pages** выберите источник **GitHub Actions**. Workflow `.github/workflows/deploy-pages.yml` опубликует сайт.

## Что работает

- регистрация и вход по email/паролю с подтверждением почты;
- показ доступных дат и атомарное бронирование: два человека не могут занять последнее место одновременно;
- отмена бронирования и автоматический возврат мест;
- профиль с личными бронированиями;
- администратор видит журнал регистраций, бронирований и отмен. Комментарии гостя сохранены в бронировании и доступны администратору через Supabase/операционную панель;
- Row Level Security: гости не читают чужие бронирования или журнал, админская роль хранится в БД, а не в редактируемом профиле браузера.

## Следующее улучшение для продакшена

Подключить Stripe через Supabase Edge Function для оплаты и webhook-подтверждения. Не стоит принимать карты в GitHub Pages или в таблицу бронирований.
